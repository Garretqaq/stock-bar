# 0001. 板块只做只读榜单，不进入自选

日期：2026-10-16
状态：已采纳

## 背景

主面板要新增「板块榜单」：把行业 / 概念 / 地域三类板块按涨跌幅排开，一眼看出今天哪些板块在涨。

东方财富的板块有代码（`BK0480`）、市场号（90）、点位与涨跌幅，看上去和一只标的没有区别 —— `90.BK0480` 甚至能直接喂给分时接口（`trends2`）画出走势。于是有一个很自然的选择：让板块也算「标的」，能加进自选、能置顶、能上菜单栏。

## 决定

**板块不是标的。** 板块榜单是一块只读视图：板块不能加入自选、不参与分组与置顶、不进「菜单栏显示」，MCP 也不暴露。板块只在板块榜单里被浏览，点开看它自己的分时。

## 理由

- 「菜单栏显示」是「价格 + 涨跌幅」的形式，而且名额有限（`BAR_MAX = 10`）。板块是点位（如 50520.08），塞进菜单栏既不好看，也白占一个名额。
- 「标的」这套规则已经渗到五处：自选（`watchlist`）、分组（`groupOf`）、置顶（`pins`）、菜单栏（`bar`）、MCP（`SUPPORTED_MARKETS` 与 `watchlist.*` 命令）。让板块成为标的，这五处都得跟着扩，而收益只是「关注几个板块」。
- 现有代码本来就是按「板块不是标的」写的：`marketTag()` 对市场号 90 返回 `--`，`SUPPORTED_MARKETS` 里没有 90，搜索接口的过滤也会把板块丢掉。顺着它走，比逆着它改便宜得多。

## 后果

- 板块相关的界面状态（当前视图、口径、排序、是否含细分）一律**不持久化**：主面板每次弹出都回到「自选 / 行业 / 涨幅榜」。
- 板块分时不写 `S.selected`：选中项仍然只表示「标的」，不会被一个板块 secid 污染，设置窗口与菜单栏都不受影响。
- 板块的行情有两家可挑，但**不能混**：东财的 `90.BK…`（行业 496 含二三级细分）与腾讯的 `91.pt…`（一级行业 31）是两套代码与两套分类。所以板块的 secid 自带来源，榜单跟着设置里的「数据源」走（`auto` 时东财不通自动退腾讯），而某一行的**分时跟着那一行自己的来源走** —— 换源之后屏上还留着上一家的板块，按设置的源去拉会画不出来。
- 将来若真要「关注某个板块」，正确做法是单独引入一层「关注的板块」，而不是把板块塞进 `watchlist`。
